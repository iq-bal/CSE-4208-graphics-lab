# Computer Graphics Implementation Summary

This report maps the core graphical theory requirements directly to their concrete implementation within the codebase.

## 1. Geometry & Modeling

| Concept | Implementation Location | Details |
| :--- | :--- | :--- |
| **Bezier Curve** | `vshader.glsl`<br>`fshader.glsl`<br>`main.cpp` | **Cubic Bezier** math is evaluated dynamically to displace ocean surface vertices (`vshader.glsl`) and govern depth blending curves (`fshader.glsl`). **Quadratic Bezier** geometry mathematically generates the sweeping blade structure for the Swinging Trap (`main.cpp`). |
| **Fractal** | `main.cpp` | Implemented via the `drawFractalDesertTree()` function. It uses recursive functions to autonomously construct hierarchical 3D branch structures with varying depth, spawn-angles, and geometric scales. |

## 2. Texturing

| Concept | Implementation Location | Details |
| :--- | :--- | :--- |
| **Simple Texture** | `main.cpp`<br>`fshader.glsl` | Diffuse maps (sand, stone, rust, hieroglyphs) are loaded via `loadTexture` (`stb_image`), bound to `GL_TEXTURE_2D`, and sampled in the shader via `texture(texture1, TexCoords)`. |
| **Vertex Blend** | OpenGL Rasterizer | The GPU intrinsically performs vertex blending by interpolating attributes (like UVs and normals) generated by the Vertex process across polygonal faces. Additionally, `vshader.glsl` mathematically blends spatial coordinates based on wave frequency. |
| **Fragment Blend** | `fshader.glsl` | Multi-texture blending is extensively utilized using `mix()`. E.g., blending four different textures depending on procedural radial depth calculations, and smoothly blending horizon geometry into atmospheric sky fog. |

## 3. Lighting (Sources)

| Concept | Implementation Location | Details |
| :--- | :--- | :--- |
| **Directional** | `main.cpp`<br>`fshader.glsl` | Modeled algorithmically as `pointLights[0]` placed at a massive infinite-distance (`y=200`) acting universally as the Egyptian Desert Sun casting volumetric fill light parameters across the exterior. |
| **Point** | `main.cpp`<br>`fshader.glsl` | Primary illumination logic inside the Crypt. `CalcPointLight` evaluates 3D radial limits and quadratic attenuation, physically tethered to the coordinates of `NUM_LANTERNS` in the `drawScene` logic. |
| **Spot** | `main.cpp`<br>`fshader.glsl` | `CalcSpotLight` evaluates strict angular cutoff beams. Driven mathematically in `main.cpp` by binding `spotLight.position` and `.direction` identically to the player's dynamic FPS camera vector (Headlamp/Flashlight logic). |

## 4. Shading & Illumination

| Concept | Implementation Location | Details |
| :--- | :--- | :--- |
| **Diffuse, Specular, Ambient** | `fshader.glsl` | The shader fundamentally builds its output array by separating light rays into properties: `ambient` (base brightness fallback), `diffuse` (normal vector scattering), and `specular` (reflection highlights evaluated against `viewDir`). |
| **Phong** | `fshader.glsl` | Fully implemented. The code mathematically calculates face normals and specular reflections dynamically per isolated fragment pixel! |
| **Gouraud** | *Not Implemented* | **Missing:** All light interactions are currently modeled on a per-pixel basis (Phong). To evaluate Gouraud, you must calculate light values exclusively inside `vshader.glsl` (per-vertex), passing down pre-computed colors instead of isolated vectors. |

## 5. Viewing & Projection

| Concept | Implementation Location | Details |
| :--- | :--- | :--- |
| **Perspective** | `main.cpp` (`drawScene`) | Mapped via `glm::perspective` acting upon an FOV parameter bounded specifically by the dynamic interaction struct: `camera.GetViewMatrix()`. |
| **Isometric** | `main.cpp` (`drawScene`) | Utilizes `glm::ortho()` projected via `glm::lookAt` offset to a fixed pitch/yaw (`+40, +40, +40`) relative to the active player position. |
| **Front** | `main.cpp` (`drawScene`) | Also an Orthographic box. Evaluates a dynamic camera dynamically positioned slightly ahead of the `camera.Front` vector facing directly flush with the user. |
| **Top** | `main.cpp` (`drawScene`) | Evaluates an Orthographic matrix mapped to a highly elevated Y-vector (`y=200`), enforcing `UP` as `-Z` to track the user room by room from the ceiling. |
